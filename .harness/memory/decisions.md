# 设计决策（全仓级 · `scope: *`）

只记「改了会导致什么坏掉」的那类。每条都是被质询过、并且知道代价的。

## D-1 四段纪律取代三段纪律，且升为四个顶层章节

- 决策：`改前/改中/改后` → `感知/规划/行动/反思`，占 `§〇`–`§三`，旧章后移。
- 代价：原 `§六` 被引 34 次，改号后全部要跟；裸编号重排「存在但指向别处」，存在性检查看不出来。
- 缓解：跨文件引用一律改成 `[§新号](../SKILL.md#锚点)`；`LINK004` 扩到校验锚点。
- 残余：文件内 4 处裸 `§X` 仍只能人判，`XREF` 抓不到重排同号。

## D-2 阶段表与四段并存，但不互相标注

- 决策：`flow.json` 的 6 阶段只作建设顺序清单，不承担「流程合规」举证；四段才是流程语言。
- 理由：6 对 4 是多对一，强行合并会把「入口」与「断言」两个不同验收判据塞进一格。

## D-3 表格行升级成 `###` 小节

- 原因：`§X.Y` 原本指向表格行，而 HTML 锚点只能落在标题上——不升级就永远无法锚定。
- 代价：失去一览表形态，正文 +74 行（285→359）。

## D-4 scope 四段钩子集中登记在 `scripts/hooks.py`

- 原因：每 scope 自带 `plan()/reflect()` 最少 6 行，而 6 个 scope 已在 146–151 行；
  `BUDGET001` 的 150 行只减不增，会同时越线。
- 代价：偏离「每 scope 自带」的字面。换来的是**逐条对账**——`loop` 拿表与源码 code 集比集合，
  漏登记/多登记/空都报，比「非空就算过」更有牙齿。

## D-5 一轮 = 一次提交

- 决策：`round.py` 拿 `HEAD~1` 检出到临时 worktree 跑 audit，与当前树比计数，上升即 exit 1。
- 不落状态文件：入库则每轮改一次（diff 全是噪声），不入库则 CI 拿不到。
- 不用 `git stash`：脚本不该替人保管未提交的改动。

## D-6 复盘机制：数据在仓库根，机制在 skill 里

- 决策：`retro.py` 只算数字；复盘正文由 AI 起草；工单记 `archive/retro/tasks.json`。
- 不进 `decisions.md`：§八「只能 remember，不能 observe」——AI 起草、人确认才留。
- `done` 必须带可核验证据（`commit:<sha>` 或 `path:<...>`），散文不算。

## D-7 `.harness` 只到状态层

- 原因：本 skill 的断言只有一套（`scripts/audit.py`）；再放 `verify.py` 就是同一断言写两处。
- 见 `.harness/README.md` 的逐层对照与「故意缺哪几件」。

## D-8 设计记录也属本机：`.harness` 放仓库根，不放 skill

- 前一步（D-7）把 `.harness/memory/` 放进了 skill 目录，理由是「设计决策要跟着 skill 走」。
- **推翻**：它解释的是「我为什么这么做」，不是「你拿去怎么用」。按 skill 自己的分发边界
  （「只为本机服务的目录，不进这个目录」），设计记录落在本机那一侧。
- 现形：`~/.agents/.harness/memory/`；skill 目录不再有 `.harness`，`STRUCT001` 的
  `EXTRAS` 例外同步撤掉——**为一条错判开的例外，也要跟着撤**。
- 教训：判断某东西属不属于载荷，问一句「换一个人拿走这个目录，它还有用吗」。
  设计记录没用（他不需要知道我的取舍史），用法说明有用（那在 `references/`）。
