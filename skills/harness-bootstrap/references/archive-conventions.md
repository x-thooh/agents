# 改名、归档、幂等：三件破坏性操作的落地

> 判据在 `../SKILL.md` [§十二](../SKILL.md#十二破坏性操作改名--迁移--归档)；这里是四步细节、白名单边界与断言方式。`§X` 指 `../SKILL.md`。

## 改名：断两类引用

改名会断两种引用，只查一种就会漏：

1. **显式引用**：链接、`import`、`include`、镜像里的路径。链接检查能抓。
2. **纯文本路径**：文档正文里写着的 `scripts/scopes/x.py`、配置里的字符串路径、
   命令示例。链接检查**看不见**它（没有链接语法），所以必须全库文本扫描旧名。

顺序固定为：记断链基准 → `git mv`（保留历史）→ 再跑一次、新增断链即本次改坏 →
逐个改纯文本出现位置。批次按影响面从小到大，牵连广的单独一轮、改完立即验链接。

## 归档：事件驱动，只许四件事

归档没有「归档期」这种按天数算的概念：判不出的标准不如不写。触发条件是事件——被取代、
被推翻、或已落地且不再改动。

移进归档区，除下面四件事，**其余字节一律不动**：

1. 整篇移动（`git mv`）
2. 保留原 `Status:` 行
3. 紧接其下插入 `Archived: YYYY-MM-DD`（日期取移动当次提交）
4. 修或删**入站**链接

断言方式：移动前后对正文取哈希；把第 2/3/4 项造成的差异按写死的规则归一化后，其余字节
逐字节相同。归一化规则必须写死——「靠人眼看看差不多」在第二次归档时就不作数了。

## 归档 = 冻结

冻结内容不为别处文法变化返工，所以归档笔记的**出站**链接不校验（校验它等于要求历史跟着
今天改）。但**入站**链接必须修，否则没人找得到它——没入口的归档等于删除。

**归档错了不解封**：写一篇新笔记说明哪条已不成立、当前现实是什么，链回旧的并写明为什么
引用它。解封会让归档变成第二个活动区，两个活动区之间必然漂移。

## 幂等：同一条命令跑两次结果一样

UHP Tasks §6 的要求换个说法：同一幂等键只执行一次，重试拿到的是第一次的结果，而不是再跑
一遍。agent 任务昂贵且有副作用，「多跑一次」比「慢一点」贵得多。

落地三条：命令跑两次结果一样；脚本先查目标是否已存在；迁移进度写进 `tasks/` 检查点，
中断后从检查点续。做不到幂等的步骤，先在任务记录里标「不可重跑」，别等出事才发现——
标注的成本是一行字，不标注的成本是一次重复发布。
