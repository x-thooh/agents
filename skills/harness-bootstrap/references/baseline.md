# 基线机制：为什么不预置、自建时怎么落地

> 规格本体在 `../SKILL.md` [§九](../SKILL.md#九五阶段流程顺序不能反)「基线机制」；本文件解释取舍与落地细节，改判定要改正文，
> 这里只跟着改理由。数值与格式的唯一事实源是正文那四条。`§X` 指 `../SKILL.md`。

## 模板为什么只带空账本

`templates/*/.harness/` 里 `baseline.txt` 只有注释行、`accepted.json` 就是 `[]`——**零基线**。
预置一份带内容的账本，效果是把「别人的免罪符」发给新仓库：开张就背着几十条不是自己欠的
账，之后没人能说清哪一条是自己的。给空白名单盖一个复查日期更糟：那不是免责，是给永久
豁免盖了个看起来会过期的章。所以模板只给机制与空账本，账由目标仓库自己记。

指纹规则（哪些数字抹 `#`、`path` 取文件还是目录）与规则集绑定：抹多了会把不同问题并成
一格，抹少了每次改文件都变「新欠」。模板给的是 `code + 消息数字→#` 这个默认解，改它要
连着改 `scopes/baseline.py` 与 `tests/reverse.py` 里的同一份证明。

## 自建时最容易做错的三处

1. **按集合去重**。同一（域, 路径）下的新问题会被老账吞掉：老账 1 条、现在 2 条，去重后
   仍是 1 条，于是第二次犯静默通过。所以基线的粒度是「条数」不是「有没有」。
2. **只报计数**。`基线内 12 条` 这种输出让「修掉一条老的 + 新增一条新的」在账面上互相
   抵消。要求逐条输出、每条标「基线内 / 新欠」，是让抵消无处藏。
3. **刷新时顺手调高总数**。刷新只允许「当前 ERROR 全是同一批老账」这一种前提；总数上升
   报 ERROR 是唯一能挡住「越欠越多但每次刷新都合法」的开关。

## 与其它 scope 的关系

基线是**最后一道**：它读的是其它 scope 报出来的 `(scope, path, code, message)`，因此
必须在所有 scope 之后跑。指纹只作用于 message（数字抹 `#`），不作用于 code——把 code
抹掉，新欠就和不存在的断言混在一起了。它不判断规则对不对，只判断「这批老账有没有变大」，
所以它是账本，不是断言质量的替代品。
