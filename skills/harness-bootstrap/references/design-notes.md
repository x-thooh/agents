# 设计思想：九条判据的展开

> `../SKILL.md` §二 只留每条的判据与布局表（表是布局的唯一事实源，不能外置）；
> 这里的「为什么、反面例子、怎么落地」是查的时候才读的部分。`§X` 指 `../SKILL.md`。

## 2. 规则与断言配对

每条硬规则要么有 verify 里的对应断言，要么显式标注「无断言」并写明强度来源（流程约束 /
人工纪律）。规则本体的唯一事实源放 `.harness/specs/ASSERTIONS.md` 的「约束 → 断言」表；
入口只留编号、一句话、scope 指针，且**指针本身也被断言**（指向不存在的 scope 报错）。

**别把这个表叫 `ARCHITECTURE.md`**。实测踩过：它和业务层的 `docs/architecture.md` 撞名，
两份都叫「架构」但一个答「系统现在长什么样」（人读）、一个答「哪条规则被哪个 scope 拦」
（机器可查），找「架构规范」的人第一次点错。两条治法合起来才够：

1. **换名而不是加说明**。叫 `ASSERTIONS.md`，文件名自己说清楚它是什么。给同一层里两个不同的
   东西起同一个名字，再好的 README 也救不了它。
2. **歧义在被误读的文件头部消解**，不是在别处写一句「注意区分」。第一句就写
   「本文件是规则↔断言对照；系统现状见 docs/architecture.md」。

改名按 §九 四步走：改完要全库扫旧名——链接检查只看 markdown 链接，**注释与配置文件里的
纯文本路径它看不见**（实测就在 `Makefile` 注释里漏了一处）。

**枚举值一律是常量表**：分类、状态、kind 这类闭集写在 verify 里，不藏在散文里。新增一个值，
同批改常量表 + 文档 + README，否则三处必然漂移。禁同义词——两个词表达同一分类等于没有分类。

## 3. 对会持续写回的外部工具，用「限时」而不是「禁止」

硬禁止必然被违反；可度量的限期（过渡态合法，N 天 WARN、2N 天 ERROR）可报告、可收敛。
判据是**能不能被报出来**：报不出来的禁止等于没有禁止，只是没人遵守时也没人知道。

## 4. 三边对账

文档写的 / 脚本做的 / 文件实际状态，任一漂移就是「规范」的裂缝，单看一边发现不了。
这就是 `LP001`（布局表 ↔ 模板）与 `CODEINDEX001`（清单 ↔ 源码）存在的理由：任一时刻
只有一边是真的，另两边都是它的投影。

## 5. 状态只保留三类且设写入门槛

`.harness/` 只存三类：`deliverables/`（门记录与证据，按阶段归档）、`tasks/`（活动任务，
有限保留）、`memory/`（教训与架构决策，永久；`memory/trace/` 放失败过程，可不 git 入库）。
写入门槛：**它能改变下一次的做法**——失败原因能，进度流水不能。寿命表见
[`notes-convention.md`](./notes-convention.md)。

## 6. 覆盖模型默认「少而广」

机械目录由最近祖先的 `AGENTS.md` 覆盖，用断言保证覆盖链完整；只有规则真正不同的目录
才有专属文件。「每目录一份」会稀释真差异：复制出来的规则改一处漏一处，之后没人敢删。

## 7. 脚本权限分级

低风险自动修（重新生成就能复原的派生数据），高风险只报告（改名、移动、删除、合并）；
`--fix` 前置条件是工作区除目标文件外干净。会改变归属的动作必须人看着。

## 8. 语料有生命周期：状态是位置，不是字段

一篇笔记只承载一个决策，用目录承载状态：`proposed/`（未拍板）· `implemented/`（已拍板）·
`rejected/`（被否）。判据两条：**状态是位置**——`Status:` 只是投影，必须与所在目录互校，
换状态用 `git mv`；**写入门槛**——代码能推出的不写，每篇必须有 `## 不显然之处` 段，
段在但空着即 ERROR。骨架、头五行、模块清单、`scope`、索引只派生、日期取 `git log`，全套见
[`notes-convention.md`](./notes-convention.md)。

## 9. 约定大于配置

默认行为要能应付八成的仓库；配置是例外，不是入口。判断某个值该是约定还是配置，只问一句：
**一半以上的仓库会用同一个值吗？** 会，它就是约定，写进目录结构、文件命名、头五行。

硬边界：**约定管形状，不管归属**。目录名、文件名、头五行、`summary` 长度都能约定成默认；
`scope`、`status`、`supersedes` 这类**归属声明必须显式写**——把「没写」推定成「全仓」
就是拿约定冒充事实，直接违反 §三 原则 4（缺失不是空）。约定减少重复劳动，不是声明义务。

本 skill 自己照此办事：`python3 scripts/audit.py` 不带参数就审自己（约定），`--skill-dir`
才是配置；反向 fixture 按约定住在 `tests/fixtures/<对应缺陷>/`。调度器同理：`scripts/audit.py`
只剩注册表与输出，每个 scope 各自住 `scripts/scopes/<name>.py`。读取面不止 SKILL.md 一个
文件：`references/*.md` 里指向本文件的 §X.Y 引用也检（`XREFDOC001/002`，只查存在性）——
外置之后引用不跟着改，正是亲手撞过一次的失败类。

**反面例子（真出现过）**：把硬约束的条数写成「三条」而实际列了六条。数字一写死就跟内容
漂移，所以正文不写条数——**能用结构表达的，不要用计数表达。**
