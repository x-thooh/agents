# 本 skill 自身守什么（`make check-all` 的全部内容）

> 本文件只管一件事：**这个仓库自己怎么验自己**。目标仓库该把规则挂到哪个载体上，在
> [`acceptance.md`](./acceptance.md)。正文中的 `§X` 指 `../SKILL.md` 的章节。

**本 skill 自身的门禁**（改 SKILL.md 前后都要跑，0 ERROR 才算改完）：

```bash
make check-all                            # 本地提交前与 CI 跑的是同一条命令
python3 scripts/audit.py                  # 只审本 SKILL.md
python3 tests/fixtures.py                 # 反向断言 + 覆盖闸（每个 code 逐条脉掉验敏感）
python3 scripts/audit.py --skill-dir tests/fixtures/ok-minimal   # 正对照：0 ERROR 0 WARN
```

`make check-all` 是本文件四段命令的超集；上面单独列出，是为了改一处时不必等全量。

**期望清单只有一处**：`tests/fixtures.py` 的 `CASES` 表。它逐条写明每个 fixture 该报哪个 code，
跑 `make check-all` 时一起执行。这里不再抄一份——抄出来的第二份表迟早和第一份不一致，
而「表说某条规则有人守」这句话的信用就建立在这上面。新增 scope 时改那张表，不是改这里。

反向测试的断言集合：每个 fixture 只含一个缺陷，audit.py 对它各报且仅报一个 ERROR、code 精确对上——不是「某条规则报了」，是「这条规则报的」（§六 verify 规范：每个 scope 上线前跑一次反向测试）。audit.py 不审语义一致性（机器判不了），语义项由断言表的「强度」列标注为人判，按 §二.2 计入「无断言」并写明强度来源。

**覆盖闸是三道，不是一道**：① 真有 `NAME` 与 `run(` 的模块抽到 0 个 code 就报错（那是提取器失效，不是这个 scope 没有 code）；② 每个 code 都得有 fixture；③ 逐个 code 脉掉验一遍——拿掉某个 code 的期望，闸必须**恰好**报它自己，否则算「对它不敏感」。③ 是花学费换来的：早先一次只抽一个三字母的 code 做反向验证，两个字母前缀的 12 个 code 整块隐形而门禁全绿。

三项全过之外，人工只核一件事：**每条硬规则在断言表里有对应行**，没有的写明「无断言」及强度来源。

另有一项曾在人工清单里，现在归 `LP001`：入口地图上的每个入口文件真实存在。人工再核一遍等于同一个断言写两处——而表是根、模板是产物，这件事本来就不是靠自觉守的。

## `audit.py` 守什么、不守什么

目标仓库侧的 scope 一个都不在本仓库里——本 skill 没有「自己的 verify」。它只有 `audit.py`：守 frontmatter 合规、目录形状、章节与条目引用存在性、相对链接存在性、调度器体征、布局表↔模板对账、基线/版本/账本这几段**文本是否写全**，外加 §二.5 的两档额度（`SECT001` 单节 / `SECT002` 参考材料：撞 80 记 WARN，超 100 记 ERROR）。一句话：**只判「规范写没写清」，不判「规范对不对」**。

后者没有断言：规则是否成立、模板是否兑现、目标仓库是否照做，全部是 §十 的人判项。这是本 skill 的已知空洞，不是遗漏——写在这里，免得下次又有人从全绿推出「这套东西是对的」。

## 现在真的是 0 WARN，而那是有条件的

自己审自己现在报 **0 ERROR / 0 WARN**。之前那条永久 WARN（外部链接未检查）不是被关掉，是把两件事分开了：

| 写法 | 含义 | 本 scope 行为 |
| --- | --- | --- |
| 内联 `[文字](https://…)` | 承诺可查 | 不查就报 LINK001；`--check-links` 时报 LINK002/LINK003 |
| 脚注 `[^x]: <https://…>` | 引用他人材料的出处，不替它背书 | 不管 |

所以**新加一条内联外部链接，这条 WARN 会回来**——那是设计，不是回退。要么真去查，要么降成脚注。
