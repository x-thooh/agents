# 文档额度：单节 80 准备拆、100 必须拆

> 本文件从 `../SKILL.md` 的 [§五.5](../SKILL.md#5-状态只三类--写入门槛) 拆出（额度只减不增，细节外置）。正文中的 `§X` 指 `../SKILL.md`。
> 数值的唯一事实源是 `scripts/scopes/common.py` 的 `DOC_WARN` / `DOC_LIMIT`（文档）与 `CODE_WARN` / `CODE_LIMIT`（代码），
> 本文件只解释语义。写在这里的数字是为了可读，改额度要改 common.py——两处写死同一串数字，迟早对不上。

上限必须是常量，不是形容词：写在 verify 的常量表里，超限即报。**「有上限」而无数值、无断言，等于没有上限。**

额度默认**只减不增**。动这两个常量要单独一轮，在 `decisions.md` 写明谁批的、为什么，不许顺手调高。

**额度从现状起算，不是拍脑袋的整数**：取「现状 + 约 10%」。这样额度贴着实际长度长，拆的时机
由内容决定而不是由一个好看的数字决定；想上调必须写理由，否则等于把棘轮拆了换个摆件。

**WARN 是 ERROR 额度的四分之三到五分之四**，不是一半：文档 80/100（80%）、代码 150/200（75%）。
比例本身没有意义，有意义的是**留出的余量够不够一次「把成段细节搬出去」的搬迁量**——文档 20 行、
代码 50 行，都够一次搬迁。余量比这更小，撞线时唯一能做的就是删内容腾地方；余量比这更大，提示来得
比问题早。早先试过把 WARN 压到额度的一半，实测几乎每条都响，人被训练成忽略它——**告警一旦恒响
就等于没有告警**。

**append-only 的日志保留额度，靠「提额 + 理由」放行**：决策日志、变更记录这类只增不减的文件
会周期性撞线。治法不是取消额度，是每次提额都逼一次「这份东西还该不该继续长」的复核
（实测一份决策日志从 80 行提到 160 行，六轮都留了理由）。反过来，逐条增删的看板与按任务归档
的产物不进额度：给它们设上限只会逼人删证据。

阈值按对象分两类，不许混用：

| 对象 | 特征 | 阈值 | 超了怎么办 |
| --- | --- | --- | --- |
| 参考材料（坑清单、字段表、验收命令） | 要用时去查，不按顺序读 | 单文件 **80 WARN / 100 ERROR** | 外置到 `references/`，入口只留判据与链接 |
| 流程手册（本 SKILL.md） | 必须整篇读完才能干对活 | **总量 400 WARN / 500 ERROR** + **单节 80 WARN / 100 ERROR** | 把成段细节外置，保留标题与判据 |
| 代码文件（`<skill_dir>/scripts/` 与 `<skill_dir>/tests/`，`tests/fixtures/` 除外） | 改的时候整份要读 | 单文件 **150 WARN / 200 ERROR** | 按职责分文件；不是抽注释 |

判归属只问一句：**这东西是「要用时去查」还是「按顺序读」？** 查的外置，读的留在手册里——但任何一节都不许长成第二个手册。

两档不是一个数：80 是**准备拆**，100 是**必须拆**。等到撞线才动手，等于每次都靠删内容腾地方——[§五](../SKILL.md#五设计思想跨仓库通用) 上一次就是从 102 行压回 100 的。80 给的是 20 行余地，让人在还有地方可放的时候就开始搬。两个档位都是断言（`SECT001` 单节 / `SECT002` 参考材料单文件），不是纪律。

**为什么手册也要总量额度**：单节额度管「哪一段太长」，管不了「一共多长」。九节各 60 行、
每节都合规而总量 540 行，读的人仍然要整篇读完——手册的加载成本按总量算，不按最大值算。
所以总量与单节是两个断言（`BUDGET002` / `SECT001`），不是同一个数的两种说法。

**额度是上限，不是目标**：把「不越线」当目标，行为会退化成「把节压回 79 行」——一轮加 76 行、
每节都刚好贴着 WARN 线，账面全绿而手册胖了一圈。这是把代理指标当目标函数的经典副作用，
再加一个阈值治不了它（新阈值会成为新的下沿）。所以判据补了一条**环比**：`scripts/round.py`
除了比 audit 计数，还比 `SKILL.md` 行数，一轮涨过 20 行即失败——20 是一节额度的四分之一。
它管的是「这一轮在塞内容还是在收口」，管不到「把内容在节之间搬家」，而后者对加载成本本来也无影响。

**覆盖范围写在表里，是为了不冒充**：`BUDGET001` 量 `<skill_dir>/scripts/` 与
`<skill_dir>/tests/`（后者跳过 `tests/fixtures/`）。`templates/` 仍不量——模板是
「某个业务域的答案」，按域重写的代价就是有 300–500 行的 `tests/reverse.py` 与 scope；
把同一个 200 行上限套上去，只会逼着把测试样本删薄。

**为什么后来把 `tests/` 加进来了**：此前只量 `scripts/`，`tests/fixtures.py` 长到 238 行、
越过自己定的 200 行之上，而门禁全绿——一句话说「本仓库由 BUDGET001 守」在字面上成立、
在覆盖面上一半，是最容易过的自我欺骗。加进来的时候顺手把那个 238 行的文件按职责拆成了
`cases.py`（期望表）/ `coverage.py`（三道闸）/ `fixtures.py`（引擎）：本条规则的第一次生效，
就是让自己红一次。

**代码的阈值为什么不一样**：行数不是文体的可读性标尺，代码里一小半是空行、注释与 `import`，同一个 80 放在脚本上会把 24 行的 scope 也标成「该拆」。所以代码沿用一个既有的上限 200，150 是它的四分之三——仍是「提前一段提醒」同一个意思，只是基数按代码的体量定。由 `budget.BUDGET001` 断言，**调度器也算在内**：`layout.LAYOUT001` 只管「调度器里有没有长出 scope 实现」那两个体征，体量归 `budget`，同一个数不写第二遍。
