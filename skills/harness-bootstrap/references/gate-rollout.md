# 门禁上线：从「能跑」到「可信」

> 判据在 `../SKILL.md` [§九](../SKILL.md#九五阶段流程顺序不能反)「门禁上线」；这里是上线顺序、
> 反例与判据。`§X` 指 `../SKILL.md`。下面每节都对应一次实测：门禁全绿，而它什么都没守。

## 1. 分期上线：先窄后宽

新门禁一次铺满全仓，第一跑就是几十条 ERROR。这时唯一能做的是把规则调到刚好不报——额度提到
现状、检查缩到一个目录——门禁从上线那天起就是装饰。做法是先窄：额度只强制根入口、子目录记
TODO，scope 先上能硬断言的（链接、目录对账、布局表），语义类留「无断言」并写强度来源。

判据：上线那一跑的 ERROR 数必须是你准备当场修完的量（个位数）。超了就是范围划大了，拆。

实证：根入口额度 80 行先只检根，子目录 119 行暂不检，缺口挂 TODO；首跑绿，后面才敢加。
「先不检」写进断言表的 TODO 列，不写成「已覆盖」。

## 2. 聚合口径：只含已落地、且提交时跑得完的

`make check` 里挂一条天天红的检查，等于训练所有人 `--no-verify`。两类具体形态：

- **账本已上线，聚合里还挂着裸测试**：已登记的失败包天天红。账本版入口（`check-test`）进聚合，
  真相入口（`make test`）保留给人单独跑——两个入口，两种用途，不互相代替。
- **慢 scope 硬塞进 pre-commit**：每次提交慢一分钟，绕过率立刻上来。登记 `slow_scopes`，
  默认跳过并**明说跳过了谁**（见 [`process-notes.md`](./process-notes.md)）。

判据：从干净 clone 跑一次聚合必须 0 ERROR。做不到就先别进聚合——「暂时红着」的条目会被读成
噪声，然后连真红一起被忽略。

## 3. 环境未就绪 ≠ 欠账

生成物不入库（`*.pb.go`、`wire_gen.go`、`conf.pb.go`）时，没跑生成器，`go vet` 输出的是 import
错误，而行形态与语义债一模一样（`path.go:1:2: no required module provides package …`）。按
findings 计数就变成几十条「新增问题」，于是**正确动作（跑生成）被伪装成错误动作（往账本里灌
假豁免）**。

治法：`err != nil` 时先独立判构建（`go build ./...`），不通只报一条 `VET_BUILD_FAILED` /
`TEST_BUILD_FAILED` 并附 fix 提示，不按（路径, code）记账——账本条数不变，环境问题不冒充实债。

判据：把生成物临时移走重跑，只应多出**一条**环境错误，不是一片新欠。
实证：未跑生成时 verify 报 17 条 ERROR，换算成（路径, code）账本却是 36 条新欠 + 8 条陈旧——
同一个缺失的生成物在多个 scope 里各记一次，**记账条数比 ERROR 数还多**，于是「该跑生成」被读成
「新增 44 条欠账」，接下来那个动作就是往 `accepted` 里灌假豁免。

## 4. 派生产物：排除自指、生成即重算相等、输入取入库集

- **自指**：索引/清单类产物必须排除在它自己的扫描面之外，否则「生成完立刻 STALE」。首次反向
  测试抓到的就是这个抖动——不是源头脏，是产物在数自己。
- **幂等**：断言形式只能是「当场重算的字节 == 盘上的字节」；「文件存在」「比上次新」都不算。
  生成器必须确定性：同一输入在两台机器上重算，字节相同。
- **输入基准**：取 `git ls-files`（含暂存），不取磁盘遍历。磁盘会把 `.DS_Store`、`cache/`、
  `cert/`、未入库的生成物收进索引，结果是「谁的环境干净谁过」。实证：已入库的索引里有 163 条
  只在他机存在的路径，本机重算又新增 `.git`（worktree 下它是文件）。
- 代价写进文档：新文件 `git add` 之后才进索引（与目录对账同口径）。

## 5. 文档与代码同批

规则/决策文档（`AGENTS.md`、`ASSERTIONS.md`、`decisions.md`、`conventions.md`）与对应代码必须
同一个 commit；确实没有代码的纯文字修正在正文标 `[doc-only]`。

- 拆成「代码一次、文档一次」时，两次评审各缺一半，reviewer 无法判断规则改动是否与实现一致；
  第二次提交还几乎总被跳过。
- 能断言的部分交给 commit-msg 钩子：这批改了代码却没改断言表/决策文档，就是混批信号。
  比写在纪律里可靠——纪律没有退出码。
- 反向同样成立：代码先变、文档没跟着变，与文档没写是同一件事。

## 收尾：通不过率决定门禁的寿命

「门禁只能靠绕过通过就等于没有」是慢 scope 分离、worktree 路径修正、外部钩子排除这三处修正的
共同理由。上线后定期问一句：最近十次提交里，有几次是靠 `--no-verify`、环境变量排除、临时提额
过去的？有，先修那条门禁，别先修人。
