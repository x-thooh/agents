# 踩坑记忆

## L-1 断言存在 ≠ 断言覆盖到

- 现象：`LINK004` 加上锚点校验后全绿，而 32 处 `references/` 锚点一条都没被查——
  `check_relative_links` 拿的 `ctx["text"]` 里只有主文档。
- 根因：写断言时只想「判什么」，没想「读哪些文件」。新增第二个消费方时读取面没跟着扩。
- 断言：`loop` 只管四段分列；本条属「断言自身的覆盖边界」，**无断言、人判**。

## L-2 新交付物第一次出现，必然没人点名

- 现象：`hooks.py`、`round.py`、`retro.py` 三个新文件，第一次提交全被 `DLV001` 打回。
- 根因：注意力全在机制本身，「谁点名它」是另一件事。
- 断言：`DLV001`。

## L-3 生成器把单元素元组写成字符串

- 现象：`hooks.py` 里 `("SCOPE001")` 不是元组而是字符串，`set()` 把它拆成字符，
  对账直接误报「漏登记 + 多登记 8 个字母」。
- 根因：单元素元组必须带尾逗号；生成代码时按「拼接」写的，没按「Python 字面量」写。
- 断言：`LOOP004`——对账比的是集合，格式一错立刻炸出来。

## L-4 额度只减不增，加功能先算行数

- 现象：`BUDGET001` 这一轮判了我四次（`audit.py` / `links.py` / `deliverable.py` / `retro.py`），
  每次都是 reformat 或加功能把文件顶过 150 行。
- 根因：加机制时默认「多写几行没关系」，而额度线是硬约束。
- 断言：`BUDGET001`。
