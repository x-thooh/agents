# 任务看板

`board.json` 是活动任务的唯一入口：`stage` 必须能在 `workflow/flow.json` 里找到，
`status` 只能是 `todo` / `doing` / `blocked` / `done`。

- 一个任务一行，`id` 与 MR、门记录里的引用一致。
- `done` 的任务不删，保留到本迭代结束再归档（归档不是删除，是移到 `board.archive.json`）。
- 看板不是进度流水：只记「还没做完什么」，不记「今天做了什么」。

## 一个任务一棵树

`make task-new TASK=T-143` 开树（同级 `<repo>-wt/T-143`，分支 `task/T-143`），
`make task-done TASK=T-143` 收尾。收尾的顺序不许颠倒：**先提交，再删树**——删树会把
未提交的改动一起丢掉，所以脚本先查工作区干净、再查分支已合并，两条都过才动手。

树与状态对不上由 `worktree` scope 报：任务 `done` 而本机还留着树是 WT001（收尾只做了
一半），任务还是 `todo` 却已经开了树是 WT002（顺序反了）。「忘了开树」判不了——任务
可能在别人机器上做，所以那条写在 `AGENTS.md` 的硬规则里，靠人守，不拿弱断言假装守住。
