# 软件交付流程 v1.2

> 每个阶段固定四格：**RACI、预期、执行、检查**。流程正文是判据来源；机器可读证据放在
> `.harness/`，由 `verify.py` 校验。

## 0. 角色与通用规则

**RACI**：A=最终批准（每阶段 1 人）；R=实际执行；C=双向咨询；I=单向知会。
质量门（CR、提测）的 A 尽量不由交付者本人担任；无法避免时在门记录注明，并加 1 名独立复核人。

**通用规则**

1. 准入/准出必须写成：判据、阈值、证据、判定人、机器/人判。
2. 证据只认链接、单据 ID、提交哈希、报告 ID、签字。
3. 变更（PRD/范围/契约/方案/排期/环境）走变更单：影响、审批人、通知、重新基线、回滚。
4. 例外必须有责任人、理由、批准人、到期日；到期即失败。
5. P0/P1 未清零不得过门；P2/P3 有责任人和期限。
6. 返工必须记录，修复后重跑受影响阶段，不得跳阶。

## 1. 需求分析

**RACI**：A=PO；R=PO/BA；C=Dev、QA、Arch、Sec、PM；I=相关方。

**预期**
- 目标：把业务问题变成可验收、可拆分、可测试的需求基线。
- 准入：业务目标/问题、来源、用户、初步范围、相关方、目标上线时间明确。
- 准出：PRD 基线（版本 + 哈希 + PO/QA/Arch 签字）；需求有唯一 ID、可测验收标准、优先级、目标版本；NFR 覆盖性能/安全/可观测性/兼容性；任务卡 1 到 `quality.json.task_max_days` 人天，超限拆卡并标依赖；影响面与需求跟踪矩阵齐全。

**执行**：需求获取 → 范围与非目标 → 优先级与验收标准 → NFR/安全/合规 → 存量影响 → PRD 评审基线 → 拆分任务卡 → 建跟踪矩阵。

**检查**
- 机器：`requirements` scope 校验 PRD 字段、任务工时、依赖环、NFR 类别、跟踪覆盖、影响面。
- 人判：需求是否解决真实问题、优先级是否合理、验收标准是否可测。
- 失败：字段/NFR 缺失退回；>3 人天拆卡；影响面缺失重做分析。

## 2. 技术方案评审

**RACI**：A=Arch；R=方案作者；C=PO、QA、Sec、DBA、Ops；I=PM、Dev。

**预期**
- 目标：形成可实现、可测试、可运维、可回滚的方案，并冻结契约。
- 准入：方案在评审前至少 `quality.json.doc_lead_business_days` 个工作日发出；开发/测试/产品/架构已通知；需求已基线。
- 准出：结论明确；P0/P1 设计问题有责任人和期限；“修改后通过”在 `quality.json.re_review_business_days` 个工作日内复评；QA 确认可测、PO 确认满足需求；契约字段/类型/错误码/示例/版本冻结并签字。

**执行**：方案覆盖模块/边界/数据流/表/第三方/选型 → 接口/状态机/异常/幂等/并发/事务 → 安全/性能/可观测性/迁移/回滚/兼容/测试策略 → 评审会 → 修改复评 → 冻结契约。

**检查**
- 机器：`design` scope 校验文档前置工作日、参与方、结论枚举、问题字段、复评时限、契约签字。
- 人判：设计合理性、可维护性、可测性、需求满足度。
- 失败：“修改后通过”限期复评；“驳回”重做；契约变更走变更流程。

## 3. 功能开发

**RACI**：A=Dev lead；R=开发 owner；C=Arch、QA；I=PM、PO。

**预期**
- 目标：按冻结契约完成可构建、可测试、可评审的代码。
- 准入：任务已排期、负责人明确；契约冻结；分支/环境/CI/lint 就绪。
- 准出：任务验收标准实现；单测通过；覆盖率按 `quality.json` 阈值；SAST/依赖/secret 无阻断；commit 规范并关联任务；构建无阻断告警。

**执行**：实现 → 单测 → CI（lint/build/test/SAST）→ 覆盖率 → 自检 → 小颗粒度提交 → MR。

**检查**
- 机器：`dev` scope 校验任务状态、测试、覆盖率、CI/SAST/build、commit 正则。
- 人判：代码质量、验收标准满足度。
- 失败：CI 红先修；覆盖率不足补测试或走例外；阻断告警清零。

## 4. 联调

**RACI**：A=Dev lead；R=联调负责人；C=QA、Ops、Arch；I=PM、PO。

**预期**
- 目标：跨服务/前后端在真实或高保真环境按契约互通。
- 准入：接口已部署；依赖/mock/数据就绪；契约版本一致。
- 准出：所有接口通过；字段/空值/枚举/边界/错误码/分页/鉴权/超时/重试/幂等/限流/降级/日志/trace 逐项验证；契约测试通过；变更记录齐全；无 P0/P1。

**执行**：部署联调环境 → 契约测试 → 逐项验证 → 记录变更 → 修复重测。

**检查**
- 机器：`integration` scope 校验接口状态、验证项集合、契约测试、环境差异、变更字段、缺陷计数。
- 人判：边界与异常覆盖。
- 失败：契约不一致先修/走变更；P0/P1 阻断。

## 5. 开发自测

**RACI**：A=Dev lead；R=开发 owner；C=QA；I=PM、PO。

**预期**
- 目标：提测前证明功能、边界、异常、兼容性可用。
- 准入：联调通过；清单按功能点/验收标准生成；数据环境就绪。
- 准出：执行率 100%、通过率达到 `quality.json` 阈值；正向/异常/边界/校验/兼容/权限/幂等/并发/回滚覆盖；P0/P1 清零；提测准入条件在本阶段内联验证。

**执行**：生成清单 → 执行 → 记录缺陷 → 修复回归 → 核对提测准入 → 出报告。

**检查**
- 机器：`selftest` scope 校验清单、执行率、通过率、缺陷、提测就绪、报告路径。
- 人判：用例质量、边界覆盖。
- 失败：P0/P1 或低于阈值先修；不允许跳过。

## 6. 代码评审

**RACI**：A=Tech lead/Arch（核心）；R=评审人 + 作者；C=QA、Arch；I=PM。

**预期**
- 目标：合并前关闭正确性、安全、性能、可维护性问题。
- 准入：MR/PR；行数上限见 `quality.json`（超出拆分或书面批准）；自测通过；CI 绿。
- 准出：评审人数达到 `quality.json` 阈值；作者不得自批；意见闭环；无未解决安全/性能/正确性问题；扫描通过；已合并。

**执行**：作者自检 → 小 MR → 评审 → 修改回复 → 专项检查 → 审批合并。

**检查**
- 机器：`review` scope 校验行数、评审人数、审批、作者回避、意见闭环、扫描、合并。
- 人判：设计与代码质量。
- 失败：阻断意见未闭环不合并；超行数拆分或书面豁免。

## 7. 整体功能自洽

**RACI**：A=QA lead；R=QA；C=PO、Dev、Arch、Ops；I=PM。

**预期**
- 目标：证明完整业务链路、数据、状态、PRD 验收、存量回归自洽。
- 准入：所有功能开发/自测/CR 通过；测试环境完整；E2E 稳定。
- 准出：跨模块/服务/角色链路走通；数据一致、状态衔接；PRD 跟踪矩阵每条有证据；存量回归无新增 P0/P1；NFR 有报告。

**执行**：E2E → 数据/状态校验 → PRD 对照 → 回归 → NFR 验收。

**检查**
- 机器：`coherence` scope 校验 E2E、跟踪矩阵覆盖、回归、NFR、已知问题。
- 人判：业务自洽性、PRD 符合度。
- 失败：遗漏/多做先修；回归失败阻断；NFR 不达标修复或例外。

## 8. 提测

**RACI**：A=QA lead；R=Dev/QA；C=PO、PM、Ops；I=相关方。

**预期**
- 目标：把可测试、可部署、可回滚的版本和完整证据交给测试。
- 准入：第 1–7 阶段准出；测试环境部署；配置/DB 变更执行；回滚演练；数据/冒烟就绪。
- 准出：提测包 manifest 齐全；QA 接收；冒烟达到 `quality.json` 阈值；无 P0/P1；版本 tag/commit/环境一致。

**执行**：组装提测包 → 部署测试环境 → 执行配置/DB 变更 → 冒烟 → QA 接收 → 移交。

**检查**
- 机器：`submission` scope 校验 manifest、冒烟、版本、QA 接收、回滚、缺陷。
- 人判：材料质量、风险接受。
- 失败：冒烟失败打回开发；修复后重跑受影响阶段并重新提测。

## 9. 发布衔接（若覆盖上线）

**RACI**：A=Ops/SRE；R=Ops/Dev；C=QA、PO、Sec；I=PM。

**预期**：生产部署可观测、可回滚、可验证；灰度指标在阈值内；上线后 N 天无异常。

**执行**：发布计划 → 流水线部署 → 灰度观察 → 冒烟/合成监控 → 上线后验证 → 发布说明。

**检查**：机器判流水线/指标/监控/回滚；人判业务验收。失败触发回滚与复盘。

若发布不在本流程内：第 8 阶段签署《发布移交单》，流程止于提测。

> 本 harness 首版不含 release scope；若把上线纳入门禁，新增 `09-release.json` 与 `release` scope，并在 `AGENTS.md` 路由表登记。

## 10. 度量与复盘

记录各阶段周期、门通过率/打回率、返工率、CR 时长、逃逸缺陷、覆盖率、冒烟通过率、变更失败率、MTTR；版本/迭代后复盘，行动项有责任人和期限，并回写流程与模板。
