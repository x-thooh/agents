# 校验命令与红点判读

按顺序跑，越靠前越便宜。全部通过 `make` 入口调用——仓库规则通常禁止直接跑 `python3 .agents/scripts/…`。

## 命令表

| 命令 | 查什么 | 典型耗时 |
| --- | --- | --- |
| `make find Q="…"` | 写前查重，返回分数与命中路径 | 秒级 |
| `make note P="<路径>"` | 单篇：单一性、体例标记、末节、出处、一句话定位字数、结构统计 | 秒级 |
| `make check` | 全库所有域 | 十秒级 |
| `make check-<域>` | 单域：`areas` `books` `folders` `harness` `inbox` `links` `schema` `single` `stale` `style` | 秒级 |
| `make wb-render` | 刷新首页/工作台数字（会改文件，要单独提交） | 秒级 |

`make note` 的输出长这样，先看「判定」再看结论：

```
判定：单一知识点
一句话定位：<这句话>（36 字）
结构：1 个一级标题 · 9 个二级小节 · 140 行
```

## 红点判读

### folders 突然几百条 ERROR

先看第一条的路径。**十有八九是某个运行目录**（`.jupymd/`、`.venv/`、`node_modules/`、工具生成的缓存目录）
在仓库根出现，且既没进 `.gitignore`，也不在 `verify` 的 `SKIP_DIRS` 里，于是里面每个子目录都被判「目录名未以数字开头」。

修法两处一起改（只改一处无效）：

1. `.gitignore` 加一行；
2. `.agents/scripts/lib/vault.py` 的 `SKIP_DIRS` 加同名目录。

不要为了让它变绿去改命名规则——那会把运行时目录固化进知识库结构。

### links 报「双链无法解析」

- 新增笔记里写的 `[[短链]]` 没有对应文件名 → 改标题或改链接；
- 收件箱里指向附件的双链失效 → 存量大面积存在，先确认不是自己引入的。

`make check-links` 只查 `[[双链]]`，**查不出纯文本路径**（`出处：04_归档/…`）。改名后必须额外扫一遍纯文本。

### schema

`area` / `moc` / `resource` 必须有 `tags`（ERROR）。数量要求：`area` / `resource` 至少 2 项（专题、分区），`moc` 至少 1 项；少于建议值只是 WARN。本库 `area` 约定写三项，第三项是主题。缺 `updated` / `by` 也是 WARN。

### books

`check-books` 会把 `028_读书/*.md` 与 `_读书汇总.md` 的行做集合比对：新增书笔记没加行 → ERROR「缺行」；汇总表多出没有对应文件的 → ERROR「多余行」。前三节应为 `核心主题 / 关键点 / 分析`，关键点少于 3 条是 WARN。`_读书汇总.md` 只允许「书名双链 / 作者 / 状态」三列。

### single

三类 ERROR 容易撞：

1. **一句话定位**：新笔记缺失即 ERROR（存量由基线降级）。40 字内；机器上限 50，别贴着机器写。
2. **分区笔记体例**（`02_领域` 下、非读书、非聚合页）：每个知识点小节带 `[必会]`/`[坑]`/`[版本]` 之一；至少一个 `[必会]`；末节是「与其他章节的衔接」；
3. **出处成色**：既无「引证/出处」小节、也无链接与归档 → ERROR；有链接但域名不在白名单（`lib/single.py` 的 `OFFICIAL_HOSTS`）、又不是本地归档、正文也没标「二手」→ ERROR，报「出处不权威」。

「与其他章节的衔接」「引证/出处」本身不带标记——它们是结构节，不是知识点。标记可以写在反引号里（`` `[必会]` ``），两种写法都认。

存量笔记大多不满足第 2、3 类。**判据是「变没变红」，不是「红不红」**：先 `make baseline` 把现状写成基线（粒度 scope+path+类别指纹，新文件不在基线里，所以新笔记照样硬挡），清理完一批后再 `make baseline` 收紧一次。

**基线不保护改动过的文件**：`git diff HEAD` 里出现过的笔记照报 ERROR，并且 `make baseline` 不会把它们写进账。想消红只有两条路——补到合规，或在任务记录里写清楚为什么不补。

### stale

首页与工作台的标记块不等于重算结果。修法固定：`make wb-render`，把这两个文件单独提交。

为什么会红：改了笔记（尤其改了最近更新的那几篇），面板里的「最近更新」「待办计数」就过时了。这不是误报——面板写着「收件箱 1634 篇」而磁盘上只剩 2 篇，就是过时。

例外（比对时两边都剔掉）：按日期或 mtime 生成的段——「周期体检」（「已过 N 天」每天变）、「最新」「最近更新」（按 mtime 排序）。它们回答的是「何时跑的」不是「仓库里有什么」：钩子里的格式化器、`git checkout`、编辑器里随手一次保存，都会打乱顺序，让断言报出与数字无关的红。

剩下被断言的是真数字：各目录笔记数、专题表、读书进度、待办计数。这些对不上就是过时，没有借口。

顺序坑：改完断言再 `make baseline`，面板里的计数会变，此时 stale 会红——再跑一次 `make wb-render` 就平。

### areas

常见 WARN：缺面包屑 `> 上级：…`、页脚缺回链（要求「上级：」出现两次）、文件名不是 `NN_主题.md`。
新写的笔记不要新增这两类 WARN——同目录的老笔记可以顺手补，但单独提交。

### style

套话黑名单（「值得一读」「众所周知」「显而易见」之类）。这类句子可以套在任何主题上，因此不承载信息。

### harness

每个 `.agents/scripts/*.py` 必须在 `Makefile` 里注册目标，否则报错。新增脚本要同时改 Makefile 与命令总表。

## 判断「是不是我引入的」

仓库通常带存量 WARN/基线。规范做法：

1. 改动前记一次 `make check` 的「合计」；
2. 改动后再记一次；
3. **数字没变就是没引入**；变了就看新增条目的路径是不是自己的文件。

不要用「反正原来是红的」跳过检查，也不要顺手把不相关的红点修进同一个提交。

## 提交前

- pre-commit 通常会自动跑 `make precommit`，红点会挡住提交；被挡住先看是不是存量问题。
- 文件名含全角括号、空格时 git 输出会转义（`02_\351\242…`），`git add` 用引号包住原路径即可。
