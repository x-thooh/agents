# 会议与决策：怎么写成可复查的笔记

会议和决策不是新的 frontmatter 类型。先按 `SKILL.md` 第 1 步判归属，再用下面的正文骨架。

## 一、先判类型，不要新造 `type`

| 材料 | 类型 | 落点 | 判据 |
| --- | --- | --- | --- |
| 项目内的决策、评审、事故复盘 | `project` | 该项目目录 | 只在当前项目/这次事故里有意义 |
| 能抽象成通用判断的决策 | `area` | 对应专题/分区 | 换项目、换团队仍成立 |
| 当天站会、1:1、随手会议纪要 | `journal` | 当天日志 | 没有独立结论，主要是过程记录 |
| 还没想清楚是纪要还是决策 | `inbox` | 收件箱 | 先原样收，之后再分流 |

**为什么不能直接写 `type: meeting` / `type: decision`**：本库 `verify.py` 按路径分类，`note-schema.md` 也没有这两个类型；只在 skill 里加类型，笔记会落成 schema 外的孤儿。要新增一级类型，先改 `note-schema.md`、`verify.py` 的 `classify` / `REQUIRED`、模板与根 `AGENTS.md`，再回来改本表。

## 二、决策笔记（ADR 风格）

适用：`project` 或 `area`。核心不是“记录我们选了 X”，而是“以后能复查为什么选 X、什么情况下该推翻”。

落 `area` 时用下面的结构，并按 area 规则加标记：

```markdown
> 一句话定位：选了 X，因为 Y；不选 Z 的代价是 W。

## 背景与约束 `[必会]`
## 选项与取舍
## 结论
## 后果与复核条件 `[坑]`
## 与其他章节的衔接
## 引证/出处
```

落 `project` 时保留 `TP_Project` 的骨架，把决策四段嵌进正文；不强制 `[必会]` 标记，但必须写清背景、选项、结论、后果与复核条件。

四条硬要求：

1. **至少两个选项**，每个给 pros / cons / 成本。没有比较的“决策”是通知，不是决策。
2. **结论可证伪**：写清什么现象说明这个决策错了，以及什么时候复核。
3. **出处**：会议记录、原始文档、实测数据；凭回忆写的段落标「推断」或「回忆」，不要写成定论。
4. **链接**：项目内决策链到项目概览/MOC；通用决策按 area 规则加面包屑与末节。

不要把「待定」「可能」「先看看」写成决策。那属于未决问题，留在会议笔记或 `inbox`。

## 三、会议笔记

适用：`project`（项目会议）或 `journal`（当天站会/1:1）。有独立结论的会议，也可以只写决策笔记，会议笔记留链接。

```markdown
# <会议名称> — YYYY-MM-DD

> 一句话定位：这次会议解决了什么，或确认了哪个决定。

## 参会人与目标
## 议程
## 讨论（立场与理由）
## 决策（链接到决策笔记）
## 行动项（负责人 / 截止）
## 未决问题
## 后续
## 出处（transcript / 录音 / 链接）
```

规则：

- **一个会议一个文件**。不要把多个会议塞进一篇日志。
- **决策单独成篇**。会议笔记只做索引：`- [[决策笔记]] — 一句话`。五个决策塞一篇，下次只会找不到。
- **行动项必须有负责人和截止**。缺一个就不是行动项，是愿望。
- **原始 transcript 不进正文**。放 `04_归档（Archive）/`，在文末给路径；正文只留提炼。需要在笔记里保留原文时，放附录并明确标「原文」。
- **没有决策也没有行动项的会议，可能不值得写**。先过 `SKILL.md` 的「写还是不写」五问。

## 四、交叉链接与收口

- 决策 → 项目/领域；会议 → 决策/行动项；项目概览或 MOC 补一行。
- 新建或改写分区笔记后，手改专题 MOC 的目录表；脚本查不出索引漏项。
- 跑 `make note P="<笔记路径>"`；项目/领域笔记再跑对应 `make check-<域>`。
- 一次只改一类；会议笔记、决策笔记、渲染出的统计页分开提交。

## 五、常见反模式

| 反模式 | 后果 |
| --- | --- |
| 会议纪要里塞五个决策 | 下次找不到某个决策；拆开 |
| 决策只写结论，不写选项 | 无法复查为什么选它 |
| 行动项没有负责人/截止 | 不是行动项，是愿望 |
| 把 transcript 全文贴进正文 | 违反单一性/篇幅；归档并链接 |
| 新造 `type: meeting` | schema/verify 不认；先改库再改 skill |
| 把「可能/也许」写成决策 | 制造伪结论；留在未决问题 |
| 会议笔记没有链接决策 | 决策变成孤岛；补 `[[链接]]` |

## 六、交付前自检

- [ ] 一句话定位能说出这次会议/决策解决了什么
- [ ] 决策至少两个选项，且有取舍
- [ ] 结论可证伪，写清复核条件
- [ ] 行动项有负责人和截止
- [ ] 重要决策已单独成篇并链接
- [ ] transcript 在归档，正文只留提炼
- [ ] `make note` 判定不是「需处理」
- [ ] 项目概览/MOC 的相关行已补
